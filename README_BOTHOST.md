## Важно
Проект использует aiogram 3.x и НЕ использует:
from aiogram.utils import executor

Если Bothost снова покажет executor в build log, значит платформа применяет старый шаблон или старую конфигурацию проекта.

## Два пользователя с одинаковыми правами

В Bothost добавьте переменную окружения:

```env
ALLOWED_USER_IDS=111111111,222222222
```

Вместо чисел укажите Telegram ID первого и второго пользователя.

Оба пользователя имеют одинаковые права:
- доступ ко всему меню;
- добавление и удаление кабинетов;
- изменение интервала;
- ручная проверка;
- просмотр статуса и событий;
- получение всех уведомлений.

Если бот раньше уже был привязан через `/bind`, сохранённый владелец тоже автоматически сохраняет доступ.

Чтобы потом добавить ещё пользователя, просто допишите его ID через запятую и перезапустите бота.


## Защита от WB API 429

- HTTP 429 автоматически повторяется до 3 раз.
- Если WB возвращает `Retry-After`, используется указанная задержка.
- Иначе применяется backoff 5 / 10 / 20 секунд.
- Между запросами бюджета добавлена пауза около 0.75 сек.
- Между двумя кабинетами добавлена пауза 5 сек.
- Временные HTTP 5xx также повторяются.
- Ошибка пользователю отправляется только после исчерпания повторных попыток.


## Добавление кабинета без seller-info

В этой версии бот больше не вызывает:
`https://common-api.wildberries.ru/api/v1/seller-info`

Причина: на некоторых хостингах этот метод может стабильно возвращать HTTP 429.

Теперь добавление кабинета выглядит так:
1. Нажмите `➕ Добавить кабинет`.
2. Введите название кабинета вручную.
3. Отправьте API-токен категории `Продвижение`.
4. Бот проверит токен через Promotion API.
5. Кабинет будет сохранён.

Название кабинета можно указать, например:
- ООО СПб-ТТ
- ООО СПБ-ТТ ГРУПП

Все остальные функции сохранены.


## Сериализация запросов WB API

В этой версии все полные проверки Wildberries защищены глобальной блокировкой.

Это означает:
- автоматическая и ручная проверка не могут идти одновременно;
- если нажать `Проверить сейчас` во время текущей проверки, бот сообщит, что проверка уже выполняется;
- если фоновый таймер сработал во время текущей проверки, новый запуск будет пропущен;
- backoff при HTTP 429 увеличен до 30 / 60 / 120 секунд;
- после добавления кабинета полная проверка больше не запускается немедленно — она пройдёт по обычному интервалу;
- между двумя кабинетами остаётся пауза 5 секунд.

Это снижает вероятность параллельных запросов и повторных 429.


## Только актуальные рекламные кампании

Бот отслеживает только кампании со статусами:
- 4 — готова к запуску
- 9 — активна
- 11 — на паузе

Архивные, завершённые, отменённые и удаляемые кампании игнорируются.

`/status` показывает только количество актуальных кампаний и количество запущенных.


## ID и название кампании

Уведомления теперь показывают одновременно ID и название рекламной кампании.

Пример:

```text
🔴 КРИТИЧЕСКИЙ БАЛАНС РЕКЛАМЫ
ID кампании: 12345678
Название: Аквафор JS500
Кабинет: ООО СПб-ТТ
Баланс: 87 ₽
```


## STRICT ACTIVE FILTER

Исправлена фильтрация архивных кампаний.

Теперь бот:
- получает список через `/adv/v1/promotion/count`;
- берёт ID только из групп статусов `4`, `9`, `11`;
- полностью исключает статусы `7`, `8`, `-1`;
- не позволяет detail endpoint вернуть архивную кампанию обратно в мониторинг;
- очищает старые архивные записи из локальной SQLite;
- название кампании берёт строго из официального поля `name`.


## V2 DIRECT
Мониторинг актуальных кампаний теперь идёт напрямую через `GET /api/advert/v2/adverts?statuses=4,9,11`.
Название берётся из `settings.name`, ID — из `id`. Архивные статус 7 не участвуют в проверке баланса.


## ARCHIVE FIX

Добавлен дополнительный фильтр по `timestamps.deleted`.

Кампания считается архивной, если:
- статус `7`, `8` или `-1`; или
- `timestamps.deleted` содержит реальную дату.

Для действующей кампании допускается:
- `deleted = null`;
- `deleted = 2100-01-01...` (техническая дата Wildberries).

Название кампании не менялось и по-прежнему берётся из `settings.name`.


## Исключённые кампании

По умолчанию бот полностью игнорирует кампанию:

```env
EXCLUDED_CAMPAIGN_IDS=23200814
```

Для неё не запрашивается бюджет, не отправляются уведомления, и запись удаляется из локальной SQLite.

Дополнительные ID можно добавить через запятую:

```env
EXCLUDED_CAMPAIGN_IDS=23200814,12345678
```


## Пополнение рекламной кампании из Telegram

Под уведомлениями о низком и критическом балансе есть кнопки:
- `➕ 1 000 ₽`
- `➕ 5 000 ₽`

После нажатия бот просит подтверждение.

Источник пополнения — `Баланс` (`type=1`) через официальный WB API
`POST /adv/v1/budget/deposit`.

Для защиты от случайного повторного пополнения используются одноразовое подтверждение,
блокировка параллельного запроса и 60-секундная защита от повторной одинаковой операции.
